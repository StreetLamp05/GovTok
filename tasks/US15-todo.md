# US15 (#18): Purge held reports after 7 days

Spec: §7.1.1 (retention). Parent: F3 Screening pipeline (#13). Depends on US5's schema (merged).

## Plan
- [x] `convex/purge.ts`: `PURGE_AFTER_MS` (7 days) and `internal.purge.purgeExpired`, an internal mutation that:
  - takes `held` reports with `createdAt` < now − 7d (`by_status_createdAt`) and deletes the clip, the frames, the meToos (`by_report_resident` prefix) and the report row
  - takes fix attempts in every status except `verified` with `createdAt` < cutoff (`by_status_createdAt`, one query per status) and deletes their clip, frames and row
  - skips storage IDs that are already gone (checked with `ctx.db.system.get`), so a missing file can't wedge the job
  - works in batches and reschedules itself (`runAfter(0)`) while a batch comes back full, to stay inside mutation limits
- [x] `convex/crons.ts`: a daily cron that calls `internal.purge.purgeExpired`
- [x] `tests/convex/purge.test.ts` (convex-test): 8-day-old held report: row, files and meToos gone. 6-day-old held report, old `open` and `fixed` reports: untouched. Old verified attempt: kept with its clip. Old unverified attempt: gone with its files.
- [x] Verify: `npm test`, `npx tsc --noEmit`, `npm run lint`, and a push to the local Convex deployment (`scripts/with-node.sh npx convex dev --once`)

## Interpretation notes
- "Unverified" means any fix-attempt status other than `verified`, including a `checking` attempt stuck for 7+ days.
- Held reports have no fix attempts (fixes are only for `open` reports, §2.1.3), so purging a report doesn't cascade into `fixAttempts`.
- `pending` reports aren't touched; the spec only covers `held`.
